O mínimo para começar

Um script é um arquivo de texto com três requisitos

  • 1Shebang na primeira linha: #!/bin/bash — diz ao SO qual interpretador usar para executar o arquivo.
  • 2Os comandos: exatamente os mesmos do Encontro 12, um por linha, na ordem de execução.
  • 3Permissão de execução: chmod +x script.sh — sem isso, o arquivo existe mas não roda.

É só isso. Nada de compilar, nada de instalar. O shell que vocês já usam é o interpretador.

Guardando informação

Variáveis: atribuir sem espaços, usar com cifrão

A sintaxe é enxuta e tem uma pegadinha que derruba todo iniciante: não pode haver espaço em volta do sinal de igual.

FormaEfeito
NOME="valor"Correto — atribui o valor à variável
NOME = "valor"Erro — o shell tenta executar um comando chamado NOME
echo $NOMEUsa o valor da variável
echo "${NOME}_backup"Chaves delimitam o nome — necessário ao colar texto junto
DATA=$(date +%F)Guarda a saída de um comando dentro da variável

A última linha é a mais útil de todas: é assim que um script captura o resultado de um comando para decidir o que fazer com ele.

Tomando decisões

Condicionais: o script escolhe o caminho

A estrutura if permite que o script reaja ao que encontrou — em vez de executar cegamente a mesma coisa sempre.

if [ condição ]; then
   comandos se verdadeiro
else
   comandos se falso
fi
TesteVerifica
-f arquivoO arquivo existe?
-d diretorioO diretório existe?
-z "$VAR"A variável está vazia?
"$A" -gt "$B"A é maior que B? (números)
A regra que evita a maioria dos bugs

Sempre use aspas em volta das variáveis

Se uma variável estiver vazia ou contiver espaços, o shell a expande de forma inesperada e a condição quebra — ou pior, o comando age sobre o alvo errado.

Sem aspas — frágil

if [ $NOME = "joao" ] — se $NOME estiver vazio, a linha vira if [ = "joao" ] e dá erro de sintaxe.

Com aspas — seguro

if [ "$NOME" = "joao" ] — mesmo vazia, vira if [ "" = "joao" ], que é falso e não quebra nada.

Vale para nomes de arquivo também: rm $ARQUIVO com espaços no nome apaga coisa errada; rm "$ARQUIVO" não.

Repetindo

Laços: o mesmo tratamento para muitos itens

Aqui o script finalmente supera o coringa do Encontro 12: em vez de aplicar um comando a muitos arquivos, ele aplica uma sequência inteira de decisões a cada um.

for

Percorre uma lista conhecida

Arquivos de um diretório, uma faixa de números, itens de uma variável. É o laço mais usado em automação.

while

Repete enquanto a condição valer

Usado para ler um arquivo linha a linha ou aguardar até que algo aconteça.

Combinado com if, o for resolve tarefas como "para cada log com mais de 7 dias, compacte e mova para o arquivo morto".

Organizando

Funções: dar nome a um bloco que se repete

Quando o mesmo trecho aparece em vários pontos do script, vira função. O ganho não é só escrever menos — é ter um só lugar para corrigir quando algo mudar.

log() {
   echo "[$(date +%T)] $1" >> /var/log/meu.log
}
log "backup iniciado"   ← chama a função com um argumento

Dentro da função, $1 é o primeiro argumento recebido, $2 o segundo, e assim por diante — a mesma convenção que vale para os argumentos do próprio script.

Saber se deu certo

Código de saída: como um script conversa com outro

Todo comando devolve um número ao terminar: 0 significa sucesso, qualquer outro valor significa erro. É assim que scripts encadeiam decisões de forma confiável.

ConstruçãoSignificado
$?Código de saída do último comando executado
cmd1 && cmd2Executa cmd2 só se cmd1 deu certo
cmd1 || cmd2Executa cmd2 só se cmd1 falhou
exit 1Encerra o script sinalizando erro a quem o chamou

Vocês já usaram && desde o Encontro 5 sem saber que era isso — agora dá pra usar de propósito.
