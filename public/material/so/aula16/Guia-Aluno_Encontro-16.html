PARTE 1 · FINALIZAÇÃO

Checklist de entrega — confira item por item

Percorra esta lista com a equipe reunida. Cada item não marcado é ponto perdido identificável.

  • deploy.sh sobe o serviço e roda duas vezes seguidas sem erro
  • Container configurado com --memory e volume
  • backup.sh gera arquivo com data no nome, em destino separado
  • Testamos restaurar de verdade — não só planejamos
  • monitor.sh coleta 3 métricas e compara com limites configuráveis
  • Os três scripts têm função de log e código de saída correto
  • Ao menos um script está agendado no cron, com caminho absoluto
  • Todas as variáveis estão entre aspas nos testes e comandos
  • README.md cobre todos os itens da seção 5 do enunciado
  • O README explica por que escolhemos cada limite de monitoramento
  • O README conecta o projeto a pelo menos 3 conceitos da disciplina
  • Testamos o toolkit na máquina de mais de um integrante
ARMADILHAS DE ÚLTIMA HORA

O que mais custa nota nesta etapa

Mais comum

README de última hora

Vale nota e é o item mais negligenciado. Escrevam hoje, não na véspera — e incluam as limitações conhecidas.

Mais arriscado

Restauração nunca testada

Vai ser pedida na demonstração. Se nunca testaram, vai falhar ao vivo — teste agora.

Mais frustrante

Só funciona numa máquina

Caminhos fixos do usuário que escreveu. Testem na máquina de outro integrante hoje.

Mais evitável

Limites sem justificativa

Números escolhidos ao acaso. O README precisa explicar o raciocínio por trás de cada um.

PARTE 2 · ENSAIO

Ensaio cronometrado — como funciona

Mesma lógica do ensaio de container do Encontro 7, agora para a apresentação inteira. Duas equipes se apresentam uma para a outra.

  • 1Apresentem o toolkit em 10 minutos cronometrados — com cronômetro de verdade rodando.
  • 2Incluam a demonstração ao vivo: subir o serviço, rodar o monitor, restaurar um backup.
  • 3A equipe ouvinte anota: o que ficou claro, o que ficou confuso, e se o tempo estourou.
  • 4Troquem e repitam. Depois, cada equipe ajusta o que o feedback apontou.

Prepare um plano B. Se a demonstração depende de algo dar certo na hora, combinem agora o que fazer se falhar: um print de evidência, um segundo terminal já preparado, ou uma explicação pronta. Improvisar sob pressão raramente termina bem.

DIVISÃO DA FALA

Todos apresentam, todos respondem

Participação equilibrada é critério avaliado, e qualquer integrante pode ser questionado sobre qualquer parte do trabalho.
